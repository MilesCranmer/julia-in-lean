# Fixes for the review of Compiler_src_typeutils

Responses to the 16 HOLLOW rows of `Compiler_src_typeutils.tsv` (review commit 0cabcb8). The model
(`JuliaLean/Compiler/src/typeutils.lean`, `typeutils/lattice.lean`) is unchanged; every fix
strengthens a statement or adds one. Each strengthened statement keeps the old one as a conjunct,
so nothing was weakened. New proofs are in `JuliaLean/Proofs/Compiler/src/typeutils/Full.lean`,
`Groups.lean`, `SplitGroups.lean`, `Alias.lean` and `Final.lean`.

| Line | Function | Response |
|---|---|---|
| 12 | `isconstType` | Strengthened (`IsconstTypeFull`): `isconstType(Type{Union{}})` is true, and it is false on every object that is neither `Type{T}` nor `TypeEgal{T}`. With the old clauses this fixes the result on every input, so plain `isTypeEgal(t)` no longer satisfies it. |
| 40 | `argtypes_to_type` | Strengthened (`ArgtypesToTypeFull`) to every list of lattice elements: each non-`Vararg` argument is the result of `widenconst_split`, the `filter!` step drops exactly the `Vararg`s whose element is not a valid type tag (`FilterRel`), and the result is `Tuple{remaining...}` or `Union{}` by the `all` check. It also fixes `widenconst_split` of a non-type `Const` (its type), a `PartialStruct` (its `typ`) and a native type. A version without the filter, or without the widening, now fails it. Not stated: containment of every concrete tuple of instances, which rests on `widenconst` being an upper bound (typelattice area); noted on the entry. |
| 53 | `has_concrete_subtype` | Strengthened (`HasConcreteSubtypeFull`): for a concrete `DataType` it is the layout's flag, and for a non-concrete `Tuple` it is true exactly when every parameter (a `Vararg`'s element type) is a type or `TypeVar` other than `Union{}`. "Always true for a DataType" fails the `Tuple{Union{}}`-style case. |
| 59 | `valid_as_lattice` | Strengthened (`ValidAsLatticeFull`): `Type{v}` and `TypeEgal{v}` are valid for a type or `TypeVar` `v`; a `UnionAll` gives the result of its unwrapped body; with `astag` a struct `DataType` gives `has_concrete_subtype` and a non-struct `DataType` gives true; every other object gives false. A version that ignores `astag` or rejects every `Type{T}` now fails it. |
| 83 | `valid_typeof_tparam` | Strengthened (`ValidTypeofTparamFull`): true for `Symbol`, `Module` and every bits type; false for a non-concrete type and for a concrete type that is no `Tuple`/`NamedTuple`; for a concrete non-bits `Tuple`, true exactly when every parameter is valid (the recursive loop). "Always false" and "no recursion" now fail it. Two gaps are noted on the entry: the model evaluates `isbitstype(t)` before the `Symbol`/`Module` test (Julia short-circuits), so each case assumes that call returns, and the `NamedTuple` step (`t.parameters[2]`) is not stated. |
| 164 | `_typename` fallback | Strengthened (`TypenameFull`): the result is `Union{}` for every object that is not a `TypeVar`, `Union`, `UnionAll`, `DataType` or `Type{T}`, which covers `Union{}`, `TypeEgal{T}`, `Vararg` and values. The difftest input set includes `Core.TypeEgal{Int}` (difftest/compiler/typeutils.jl:72), so the `TypeEgal` case agrees with Julia. |
| 166 | `_typename(::Union)` | Strengthened (`TypenameFull`): when the members disagree, the result is `Union{}` if one gives `Union{}` (line 170), `Union{}` if both give different `Const` names (line 171), and `Core.TypeName` otherwise (line 172). |
| 196 | `compute_alias_groups` | New entry `compiler-unionsplit-compute-alias-groups`: the result is `nothing` exactly when no `SlotNumber`/`SSAValue` repeats among the first `na` `fargs` and fewer than two of the first `na` argtypes are `MustAlias`, so "always nothing" fails it. Still not stated: which grouping is returned. That is the leader invariant of `merge_fargs_alias_groups!` and `merge_mustalias_groups!`, whose rows stay todo. The union-splitting statements below take the returned grouping as it is. |
| 216 | `any_alias_candidate` | New entry `compiler-unionsplit-any-alias-candidate`: true exactly when `AliasCandidate` holds (a repeated `SlotNumber`/`SSAValue` among the first `na` `fargs`, or two `MustAlias` among the first `na` argtypes), for every input, including `fargs !== nothing`. "Always false" fails it. |
| 291 | `unionsplitcost` | New entry `compiler-unionsplit-cost-groups` (`UnionsplitcostFull`), for every input: with the groups `compute_alias_groups` returns, followers are skipped, each leader's argument is widened with `widenconst_split` on a lattice with extended union splitting (not a `Vararg`), and the result is `min(typemax(Int), 2*prod/max(2, largest))` over the lengths read; the loop stops early only on overflow. A version that ignores followers or skips the widening fails it. The refutations are unchanged. split-count stays a documentation finding: it contradicts the `types.jl:295-297` wording, while the code comment says the cost is relative by design. subtype monotonicity stays a perf lead. |
| 321 | `switchtupleunion(ty)` | New entry `compiler-unionsplit-switchtupleunion-type` (`SwitchtupleunionTyFull`): for every `ty` whose unwrapped body is a `DataType`, the result is, in order, `rewrap_unionall(Tuple{c...}, ty)` for each member choice `c` of `cart` (by `mem_cart` and `cart_no_union`, each choice replaces every `Union` parameter by one of its members). Returning `n` copies of `ty` now fails it. The refuted coverage law still needs a `UnionAll` input that no caller passes; that entry is unchanged and stays P3. |
| 326 | `switchtupleunion(𝕃, argtypes)` | New entry `compiler-unionsplit-switchtupleunion-groups` (`SwitchtupleunionLFull`): for every input, with the groups `compute_alias_groups` returns, the result is exactly the lists of `CartG`. | 333 | `_switchtupleunion` | New entry `compiler-unionsplit-switchtupleunion-rec` (`SwitchtupleunionGroupsSpec`): for any groups, lattice and emitter, the result is `tunion` followed by one emitted value per list of `CartG`. The restore loops are run and their result is unused, as in Julia. |
| 396 | `unioncomplexity` | Strengthened (`UnioncomplexityFull`): on a `Tuple` it is the largest of the parameter complexities (0 for none), on a `UnionAll` `max(body, var.ub)`, on `Vararg{T}` `T`'s plus one, on a bare `Vararg` 1, and 0 on every other non-`DataType`, non-`Union` object. |
| 397 | `_unioncomplexity` | Same entry and statement as line 396. |
| 461 | `is_immutable_argtype` | New entry `compiler-unionsplit-immutable-argtype-widen` (`IsImmutableArgtypeWiden`): `is_immutable_argtype(a)` is `is_immutable_type` of `widenconst_split(ignorelimited(a))`.

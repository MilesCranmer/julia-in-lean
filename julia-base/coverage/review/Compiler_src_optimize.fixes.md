# Response to the review of Compiler/src/optimize.jl

Each HOLLOW row now has a new entry that gives the function's value on every kind of input,
branch by branch. The statements are in `JuliaLean/Proofs/Compiler/src/optimize/Exact.lean` and
are registered as `exactEntries` (wired into `JuliaLean/Registry.lean`). The row's earlier entries
are kept. The model did not change.

All 7 new entries are proven. Each was first checked on the pinned Julia (1.15.0-DEV.184
f755f49a9e) by the new `difftest/compiler/inlining_props.jl`, which calls the Compiler function
and compares it with the value the Lean statement gives: `PROPS OK`, no failures (counts below).

| line | function | new entry | what is now pinned |
|---|---|---|---|
| 125 | inlining_cost | `compiler-inlining-inlining-cost-exact` | The value for each kind of source: the `inlining_cost` field of a `CodeInfo`, the decoded byte of a compressed `String` and of a bare `UInt8`, and `MAX_INLINE_COST` for an `IRCode`, an `OptimizationState` and anything else (`nothing`). Bytes below 32 decode to themselves and `0xff` to `MAX_INLINE_COST`, and compressing a `CodeInfo` with cost below 64 keeps the cost. A function that returns 0 for every finite cost now fails the `CodeInfo` clause. Julia check: all 256 bytes, CodeInfo and String at the encoding edges, and `nothing`, an `Int` and an `IRCode` (585 cases). |
| 127 | is_inlineable | `compiler-inlining-is-inlineable-exact` | A `CodeInfo` is inlineable exactly when its cost is not `MAX_INLINE_COST`. A compressed `String` and a bare `UInt8` are inlineable exactly when the byte is not `0xff`. An `IRCode`, an `OptimizationState` and `nothing` are never inlineable, so `is_inlineable(nothing) == true` now fails. Julia check: 256 bytes, plus the `nothing`, `Int` and `IRCode` cases. |
| 142 | is_declared_inline | `compiler-inlining-declared-inline-exact` | For a `CodeInfo` and a compressed `String`, the result is `inlining == SRC_FLAG_DECLARED_INLINE`. The field values 0, 1 and 2 give false, true and false. Compression keeps the answer, and every other source is a `MethodError`. The constant-false function fails the value-1 clause. Julia check: `code_lowered` gives `inlining` 0, 1 and 2 for a plain, an `@inline` and a `@noinline` method, and every value 0:3 is checked on the `CodeInfo` and on its compressed `String`. `nothing`, a `UInt8` and an `IRCode` throw `MethodError` (25 cases, shared with the next row). |
| 145 | is_declared_noinline | `compiler-inlining-declared-inline-exact` | The same as the row above, with `SRC_FLAG_DECLARED_NOINLINE`: the field value 2 gives true, and the values 0 and 1 give false. |
| 355 | is_stmt_inline | `compiler-inlining-stmt-inline-exact` | `is_stmt_inline(f)` equals bit 1 of `f` for every `UInt32`, so `is_stmt_inline(0) == false`, and the constant-true function fails. It is also false on `IR_FLAG_NOINLINE` and on every result of `flags_for_effects`. Julia check: 20004 flags (bit test), plus 2000 random `Effects`. |
| 356 | is_stmt_noinline | `compiler-inlining-stmt-inline-exact` | The same as the row above, with bit 2. |
| 1793 | statement_cost | `compiler-inlining-statement-cost-exact` | Every branch's cost. Meta heads cost 0, `foreigncall` 20 (1 for `jl_string_ptr`), `foreignglobal` 1, `invoke` 20 (0 for a `Union{}` result), and `copyast` 100. A global assignment costs 3 and a local one 0, each plus an `Expr` right side priced with line -1. Any other head costs 0. The callee recovery step is stated. For calls: getfield/tuple/getglobal cost 0; the memoryref operations cost 1 or 5 when the memory argument's type is known and `inline_nonleaf_penalty` otherwise. A constant-type `typeassert` costs 1, and a one-argument `typeassert` throws `BoundsError` (the bug compiler-inlining-typeassert-one-arg, stated as the code behaves). Other builtins cost their `T_FFUNC_COST` (20 without one), and non-builtin calls the penalty (0 for `Union{}`). An intrinsic costs 20 without a table entry or outside its arity, using Julia's wrapping `maxarg + 1`, so every llvmcall costs 20. It costs its table cost k for k = 0, for fewer than two arguments, for `llvmcall` or for a non-dispatch-element argument. It costs `(k - 1) ÷ 2` when at least one argument is a constant and at most one is not. A function returning 0 everywhere now fails. Julia check: 23 constructed statements, one per branch that needs no non-constant type answer, including the halving for `add_int`, `mul_int`, `sub_int`, `mul_float` and `div_float`. The memoryref and non-constant-argument branches rely on the model difftest (200000/200000 over four seeds before this change). |
| 1909 | statement_or_branch_cost | `compiler-inlining-statement-or-branch-cost-exact` | An `Expr` costs its `statement_cost`. A `GotoNode` or `GotoIfNot` costs 40 when its target is before `line` and 0 otherwise. In a `CodeInfo` the target is the label. In an `IRCode` it is the first statement of block `label`, and a label that names no block (below 1 or past the end) is a `BoundsError`. An `EnterNode` costs `typemax(Int)` and anything else 0. Charging 0 for backward branches now fails. Julia check: every (target, line) pair in 1:6 × 1:6 on a `CodeInfo` and every (block, line) pair of a loop's `IRCode` (497 cases), plus blocks 0 and n+1 (`BoundsError`). |
| 1945 | statement_costs! | `compiler-inlining-statement-costs-exact` | The result is an equation. `statement_costs!` computes `statement_or_branch_cost(body[line], line, ...)` for `line = 1:length(body)` in order, writes each to `cost[line]`, and returns their running maximum from 0. So writing the whole sum to `cost[1]` now fails, and the first statement that throws decides the exception. Julia check: six functions, including a loop and a try/catch; `cost` matched per line and the maximum matched (12 cases). |

Proof notes. `#print axioms` was not run separately. `scripts/audit.sh`, which runs the
proof-escape check, ends with `AUDIT OK`. No new axioms, `sorry`, `native_decide` or `decide`
over large spaces were used. The intrinsic loop is characterized by `icc_exact`, by induction
over the argument list.

The change outside this area's files is two lines in `JuliaLean/Registry.lean`: an import of
`optimize/Exact` and `++ ...optimize.exactEntries`. They are needed because `Exact.lean` uses
lemmas from `optimize.lean`, so `optimize.lean` cannot import it.
